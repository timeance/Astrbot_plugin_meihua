# 梅花易数助手

AstrBot 的梅花易数排盘与解卦插件。支持直接报数、粘贴网站排盘文字，在本地核对本卦、互卦、变卦和动爻，再结合《灵签详解》64 卦知识库生成解读。

`起卦` 沿用 Bot 当前的人设和聊天上下文；`完整起卦`（别名 `解卦`）使用独立模型，完整展示排盘、知识库原文和解读。独立解卦后可用 `问卦` 补充背景，无需引用拆开的多条回复。

**v0.2.0 · AstrBot >=4.29.4,<5 · Apache-2.0**

## 快速开始

1. 在 AstrBot 插件管理中，通过仓库地址安装：`https://github.com/timeance/Astrbot_plugin_meihua`。也可上传仓库 ZIP，或将源码放入 `data/plugins/astrbot_plugin_meihua/` 后重载。
2. 普通 `起卦` 使用当前会话的聊天模型。需要独立解卦时，在插件配置中选择「独立解卦模型供应商」，推理等级可先保持 `default`。
3. 按需填写每日限额和管理员用户 ID，保存并重载插件。
4. 群聊先通过聊天软件的提及功能 @ 机器人，再发送下面的命令；私聊按 AstrBot 的唤醒设置发送。

```text
起卦 报数: 11 12
占问: 这个方案适合先小范围测试吗？
```

普通起卦需要 AstrBot 本地 Agent Runner。使用 Dify、Coze 等第三方 Runner 时，请选择 `完整起卦` 或 `解卦`，并配置插件的独立模型。插件没有额外运行依赖，也不单独保存 API Key。

## 命令与模式

| 命令 | 回复内容 | 如何追问 |
| --- | --- | --- |
| `起卦 <排盘或报数>` | 先给出排盘校验，再由当前聊天模型结合知识库解读；沿用人设、历史和已启用的其他插件 | 直接聊天追问 |
| `完整起卦 <排盘或报数>` | 独立输出排盘、命中的完整知识库原文和分层解读，不引入日常聊天的人设、记忆或历史 | 使用 `问卦` |
| `解卦 <排盘或报数>` | 与 `完整起卦` 相同 | 使用 `问卦` |
| `问卦 <补充背景或问题>` | 续接当前会话中自己的最近一次独立解卦，只回答本次问题 | 继续使用 `问卦` |

下文示例都是命令正文。若配置了 `/` 等唤醒前缀，请按实际设置添加，例如 `/起卦 11 12`。

## 输入排盘

### 直接报数

支持一个或多个正整数，默认采用 [meihua.iztro.com](https://meihua.iztro.com/) 的报数规则。只有数字时也可以发送 `起卦 11 12`；带背景时建议明确写出「报数」和「占问」。日期、预算等背景数字不会自动作为报数。

```text
完整起卦 报数: 11 12
占问: 新方案应当注意什么？
```

### 粘贴已有排盘

可以直接粘贴网站复制的表格文字，保留字段名即可。字段与值支持冒号、空格、制表符或分行，能够识别「事由」、报数、四柱、空亡，以及本卦、互卦和变卦。

```text
起卦 占问: 新方案适合先小范围测试吗？
时间: 2026年11月22日 17时25分
四柱: 丙午 己亥 庚子 乙酉
本卦: 水泽节
变卦: 坎为水
空亡: 寅卯 辰巳 辰巳 午未
```

已有本卦和变卦，或本卦和动爻时，不必另报数字。插件会推导互卦并检查内部一致性；同时提供报数和卦象时，还会比对报数结果。发现冲突会提示修正，信息不足会提示补齐后重发完整命令。

其他流派或手动排盘请标明「起卦法」或「来源」，并提供最终卦象。六位卦码需明确标注「卦码」，避免与报数混淆。目前处理文字输入，截图请先转成文字。

## 问卦续接

```text
解卦 报数: 11 12
占问: 新方案应当注意什么？

问卦 补充背景：我计划先小范围测试，预算有限。

问卦 互卦对这个判断有什么影响？
```

`问卦` 自动携带原始占问、排盘、完整知识原文、首次解读和本卦已成功完成的问答。记录按同一机器人、同一群聊或私聊、同一用户分别保存。

有效的 `完整起卦` 或 `解卦` 通过模型配置与限额检查后，会替换旧卦和追问记录。输入错误、配置错误或超额拦截不覆盖旧记录；模型请求失败仍保留新排盘，可稍后用 `问卦` 重试。普通 `起卦` 不覆盖这份独立记录。

**独立问卦记录保存在内存，重载插件或重启机器人会清空。** 普通起卦的上下文由 AstrBot 的正常聊天记录管理。

## 主要配置

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 独立解卦模型供应商 | 未选择 | 用于 `完整起卦`、`解卦` 和 `问卦`；普通起卦仍使用当前聊天模型 |
| 独立解卦推理等级 | `default` | 沿用供应商设置，或指定 `none`、`minimal`、`low`、`medium`、`high`、`xhigh` |
| 每用户每日次数 | `0` | `0` 表示不限；同一平台、同一机器人下，用户次数跨群和私聊累计 |
| 每群每日总次数 | `0` | `0` 表示不限；群内成员共用，私聊不受此项限制 |
| 管理员用户 ID | 空列表 | 填写账号 ID，例如 QQ 号；列表内账号和 AstrBot 全局管理员均豁免限额 |

独立模式支持 OpenAI 兼容 Chat Completions / Responses，以及内置 Anthropic、Gemini 供应商。自定义推理等级仅适配 OpenAI 兼容供应商；Anthropic、Gemini 使用 `default`。模型不支持所选等级时会提示失败，不自动降低等级重试。

### 每日限额

例如设置个人每日 3 次、群每日 30 次：普通成员需要同时满足两项额度；个人用满后不能继续调用，群用满后其他普通成员也需等到次日。管理员调用不扣个人和群次数，群管理员身份本身不获得豁免。

四个命令共用额度，每次通过检查进入模型解读计 1 次，失败、超时或发送失败也计次。输入无效、没有可续接的卦象、模型配置检查失败和超额拦截不计次。多段回复，以及普通聊天同一轮中的工具调用、模型重试，不重复扣次。

额度按北京时间（UTC+8）每天 00:00 重置，记录保存在 `data/plugin_data/astrbot_plugin_meihua/quota.sqlite3`，重载和重启不会清零当天次数。普通起卦后的直接聊天追问由 AstrBot 管理，不计入插件额度。

## 常见问题

- **独立解卦为什么有多条回复？** 依次展示校验结果、实际命中的完整知识原文和模型解读；较长内容还会分段。直接发送 `问卦` 即可续接全部资料。
- **为什么没有旺衰、空亡等标签？** 仅在网站规则路径和必要字段齐全时计算。只有公历时间时不会补算四柱，也不会核验用户提供的干支与公历是否一致。
- **只收到排盘，没有解读？** 普通起卦在会话 AI 关闭时只返回校验结果；开启后再试。独立模式请检查插件中的供应商与推理等级。
- **消息里会显示 Markdown 符号吗？** 插件会清理标题、加粗、反引号等常见标记，保留正文与段落。普通起卦仅在本次请求关闭流式输出并清理最终文字回复。

普通起卦通过 AstrBot 正常聊天流程补充资料，仍遵循宿主的唤醒、历史管理和其他插件设置。独立模式只发送当前卦象及本卦问答给所选模型，不调用其他插件工具，也不写入日常聊天历史。占问和背景会随解读请求发送给对应模型服务；插件自身不将正文保存到额度数据库。

## 从旧版升级

从 `0.1.x` 升级后，原来独立解卦的 `起卦` 命令改为 `完整起卦` 或 `解卦`。现在的 `起卦` 会沿用当前聊天的人设和上下文；原有模型与推理等级设置继续用于独立模式。新增限额默认不限，保存设置并重载即可。

更新内容见 [更新日志](CHANGELOG.md)。

## 开发与来源

运行要求为 AstrBot `>=4.29.4,<5`，Python 版本跟随宿主。本地验证以 AstrBot 4.29.4 为基线，检查范围见 [验证记录](VALIDATION.md)。在仓库目录运行测试：

```sh
python -B -m unittest discover -s tests -v
```

项目沿用仓库的 [Apache-2.0 许可证](LICENSE)。内置解读规则和《灵签详解》64 卦知识库来自原「梅花易数解卦助手」，排盘逻辑由 `meihua-yishu-analyst` 的确定性脚本适配；程序在本地计算，不请求 iztro 在线排盘接口。知识库为现代整理文本，解读用于传统文化学习与参考。

限额设计参考 [astrbot_plugin_openai_native](https://github.com/timeance/astrbot_plugin_openai_native)。问题反馈请提交至 [Issues](https://github.com/timeance/Astrbot_plugin_meihua/issues)，附命令格式、错误提示和版本信息，并去除私人占问与账号信息。
